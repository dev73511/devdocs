##

### What is O(1)?

**O(1)**, pronounced **"Big O of 1"**, represents **Constant Time** complexity.

An algorithm is considered O(1) when its execution time **does not depend on the size of the input dataset**. Regardless of whether the input has 1 item, 100 items, or 1,000,000 items, the algorithm will always take the same amount of time/steps to execute.

---

### Example 1: Accessing the First Item

Here is our first example:

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers) {
        // O(1)
        console.log(numbers[0]);
    }
    ```

    </Tab>

    <Tab value="Java">
    ```java
    public class Main {
        public void log(int[] numbers) {
            // O(1)
            System.out.println(numbers[0]);
        }
    }
    ```
    </Tab>
</Tabs>

### How it works:
- This method takes an array of numbers and prints the first item on the console.
- It doesn't matter how big the array is: we can have an array with 1 or 1 million items. All we are doing here is printing the first item.
- So this method has a single operation and takes a constant amount of time to run.

---

### Why Not Measure Execution Time in Milliseconds?

We don't care about the exact execution time in milliseconds, because that can be different from one machine to another, or even on the same machine.

All we care about is that this method runs in constant time, and we represent it using **O(1)**. This is the runtime complexity of this method.

So in this example, the size of our input doesn't matter: this method will always run in constant time, or `O(1)`.

---

### Example 2: Duplicating Operations (Dropping Constants)

Now, what if we duplicate this line?

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers) {
        // O(2) -> O(1)
        console.log(numbers[0]); // O(1)
        console.log(numbers[0]); // O(1)
    }
    ```

    </Tab>
    <Tab value="Java">

    ```java
    public class Main {
        public void log(int[] numbers) {
            // O(2) -> O(1)
            System.out.println(numbers[0]); // O(1)
            System.out.println(numbers[0]); // O(1)
        }
    }
    ```

    </Tab>
</Tabs>

### Why O(2) Simplifies to O(1):
- Here we have two operations. Both of these operations run in constant time, so technically the runtime complexity is `O(2)`.
- But when talking about runtime complexity, we don't really care about the number of operations. We just want to know how much an algorithm slows down as the input grows larger.
- In this example, whether we have 1 or 1 million items, our method still runs in constant time.
- So we simplify this by writing down **O(1)**, meaning constant time.

### Summary Checklist

| Metric | Details |
| :--- | :--- |
| **Complexity** | O(1) (Constant Time) |
| **Growth Rate** | Flat horizontal line (does not slow down as input size grows) |
| **Rule** | Drop constant counts (O(2) simplifies to O(1)) |
| **Scalability** | Ideal / Best scalability |
| **Common Examples** | Accessing an array item by index (`numbers[0]`), pushing/popping from a stack, hash table lookup |
