##

### What is O(1)?

**O(1)**, pronounced **"Big O of 1"**, represents **Constant Time** complexity. 

An algorithm is considered O(1) when its execution time **does not depend on the size of the input dataset**. Regardless of whether the input has 1 item, 100 items, or 1,000,000 items, the algorithm will always take the same amount of time/steps to execute.

---

### Example 1: Accessing an Element by Index

Here is how constant time lookup looks:

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers) {
        // O(1)
        console.log(numbers[0]);
    }
    ```

    </Tab>

    <Tab value="Java">
    ```java
    public class Main {
        public void log(int[] numbers) {
            // O(1)
            System.out.println(numbers[0]);
        }
    }
    ```
    </Tab>
</Tabs>

#### How it works:
- This methods take an array of numbers and print the first item (`numbers[0]`) to the console.
- **Input Size Independence**:
  - If `numbers` has **1 item**: it prints the first item -> 1 operation.
  - If `numbers` has **1,000,000 items**: it still only prints the first item -> 1 operation.
- Aaccessing an element at a specific index (`numbers[0]`) is done via direct memory address lookup in a single step.
- Because it performs a single constant operation regardless of the array's size, its runtime complexity is **O(1)**.

---

### Why Not Measure Real-World Time (Milliseconds)?

When analyzing algorithm performance, we don't worry about exact time in milliseconds because:
1. That can be different from one machine to another or even on the same machine.

All we care about that this method runs in constant time and we represent in **O(1)**.

### Example 2: Multiple Operations and Dropping Constants

What happens if we duplicate the print statement?

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers) {
        console.log(numbers[0]);
        console.log(numbers[0]);
    }
    ```
    </Tab>

    <Tab value="Java">

    ```java
    public class Main {
        public void log(int[] numbers) {
            System.out.println(numbers[0]);
            System.out.println(numbers[0]);
        }
    }
    ```
    </Tab>
</Tabs>

#### Why O(2) Simplifies to O(1):
- In this method, there are now two constant-time operations. One might say the complexity is O(2).
- However, Big O notation is concerned with **scalability**, not the exact count of instructions:
  - If the array has 1 item, it runs 2 operations.
  - If the array has 1,000,000 items, it still runs 2 operations.
- The execution time remains flat and does not grow when the input size **n** increases.
- Therefore, we **drop the constant** and simplify O(2) down to **O(1)**.

> **Rule of Thumb**: In Big O notation, constant coefficients are ignored. O(1), O(2), and O(100) all represent the same complexity: **O(1) (Constant Time)**.
