## What is O(n^2)?

**O(n^2)**, pronounced **"Big O of n squared"**, represents **Quadratic Time** complexity.

In an O(n^2) algorithm, the number of operations grows proportionally to the square of the input size (`n * n`).

- If the input has **10 items**, it runs **100 operations** (`10^2`).
- If the input has **1,000 items**, it runs **1,000,000 operations** (`1,000^2`).
- If the input has **1,000,000 items**, it runs **1,000,000,000,000 operations** (1 trillion operations!).

Because the growth curve climbs steeply, O(n^2) algorithms become very slow as the input size becomes large.

---

## 1. Nested Loops Example (Printing All Combinations)

Simple loops run in linear time or `O(n)`. But here we have nested loops, which is the algorithm we use for printing all combinations of items in an array:

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">
    ```javascript
    function log(numbers) {
        // O(n^2)
        for (const first of numbers) { // O(n)
            for (const second of numbers) { // O(n)
                console.log(first + ", " + second);
            }
        }
    }
    ```
    </Tab>
    <Tab value="Java">
    ```java
    public class Main {
        public void log(int[] numbers) {
            // O(n^2)
            for (int first : numbers) { // O(n)
                for (int second : numbers) { // O(n)
                    System.out.println(first + ", " + second);
                }
            }
        }
    }
    ```
    </Tab>
</Tabs>

### How it works:
- In our outer loop, we are iterating over our input array, which is **O(n)**.
- In each iteration, we are once again iterating over all the items in this array, which is another **O(n)**.
- So the runtime complexity of this method is `O(n * n)` or **O(n^2)**.
- We say this algorithm runs in **quadratic time**.

---

## 2. Comparing O(n^2) with O(n)

Algorithms that run in `O(n^2)` get slower than algorithms that run in `O(n)`:
- If you are dealing with a small array of, let's say, **50 items**, you are not going to see any differences.
- But as our input grows larger and larger, algorithms that run in `O(n^2)` get **slower and slower**.

## 3. Adding a Loop Before or After (Dropping Non-Dominant Terms)

Now, what if we had another loop before or after this nested loop?

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers) {
        // O(n)
        for (const number of numbers) {
            console.log(number);
        }

        // O(n^2)
        for (const first of numbers) { // O(n)
            for (const second of numbers) { // O(n)
                console.log(first + ", " + second);
            }
        }
    }
    ```

    </Tab>
    <Tab value="Java">

    ```java
    public class Main {
        public void log(int[] numbers) {
            // O(n)
            for (int number : numbers) {
                System.out.println(number);
            }

            // O(n^2)
            for (int first : numbers) { // O(n)
                for (int second : numbers) { // O(n)
                    System.out.println(first + ", " + second);
                }
            }
        }
    }
    ```
    </Tab>
</Tabs>

### Why O(n + n^2) Simplifies to O(n^2):
- The single loop runs in `O(n)`.
- The nested loops run in `O(n^2)`.
- So the runtime complexity of this method is `O(n + n^2)`.
- The square of a number is always greater than the number itself, so in this expression, `n^2` always grows faster than `n`.
- In Big O notation, we want an approximation of how the cost increases, not an exact value.
- Therefore, we **drop n** and conclude that this method runs in **O(n^2)**.

## 4. Three Nested Loops: O(n^3) (Cubic Time)

What if instead of that single loop, we had another nested loop inside?

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers) {
        // O(n^3)
        for (const first of numbers) {
            for (const second of numbers) {
                for (const third of numbers) {
                    console.log(first + ", " + second + ", " + third);
                }
            }
        }
    }
    ```

    </Tab>
    <Tab value="Java">

    ```java
    public class Main {
        public void log(int[] numbers) {
            // O(n^3)
            for (int first : numbers) {
                for (int second : numbers) {
                    for (int third : numbers) {
                        System.out.println(first + ", " + second + ", " + third);
                    }
                }
            }
        }
    }
    ```

    </Tab>
</Tabs>

### Complexity Analysis:
- The runtime complexity is now **O(n^3)** (Cubic Time).
- As you can imagine, this algorithm gets **far slower** than an algorithm with `O(n^2)`.

## Summary Checklist

| Metric | Details |
| :--- | :--- |
| **Complexity** | O(n^2) (Quadratic Time) |
| **Growth Rate** | Curved line curving upward; gets slower as `n` increases |
| **Rule: Drop Non-Dominant Terms** | In O(n + n^2), we drop `n` because `n^2` grows faster → O(n^2) |
| **Three Nested Loops** | O(n^3) (Cubic Time) — far slower than O(n^2) |
| **Scalability** | Gets significantly slower as input size grows |
| **Common Examples** | Printing all combinations/pairs in an array, bubble sort, selection sort |
