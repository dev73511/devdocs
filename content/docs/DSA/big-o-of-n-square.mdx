## What is O(n^2)?

**O(n^2)**, pronounced **"Big O of n squared"**, represents **Quadratic Time** complexity.

In an O(n^2) algorithm, the number of operations grows proportionally to the square of the input size (`n * n`).

- If the input has **10 items**, it runs **100 operations** (`10^2`).
- If the input has **1,000 items**, it runs **1,000,000 operations** (`1,000^2`).
- If the input has **1,000,000 items**, it runs **1,000,000,000,000 operations** (1 trillion operations!).

Because the growth curve climbs steeply, O(n^2) algorithms become very slow as the input size becomes large.

---

## 1. Nested Loops Example (Printing All Pairs)

The classic example of O(n^2) is a nested loop where an outer loop and an inner loop both iterate over the same array:

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">
        ```javascript
        function log(numbers) {
            // Outer loop: O(n)
            for (const first of numbers) {
                // Inner loop: O(n)
                for (const second of numbers) {
                    console.log(first + ", " + second);
                }
            }
        }
        ```
    </Tab>
    <Tab value="Java">
        ```java
        public class Main {
            public void log(int[] numbers) {
                // Outer loop: O(n)
                for (int first : numbers) {
                    // Inner loop: O(n)
                    for (int second : numbers) {
                        System.out.println(first + ", " + second);
                    }
                }
            }
        }
        ```
    </Tab>
</Tabs>

### How it works:
1. **Outer loop** runs `n` times (once for every element in `numbers`).
2. **Inner loop** also runs `n` times for **every single iteration** of the outer loop.
3. Total number of operations:
   `n * n = n^2`
4. Therefore, the runtime complexity is **O(n^2)**.

---

## 2. Comparing O(n^2) with O(n)

- **Small Inputs (e.g., 50 items)**:
  For small datasets, modern CPUs are so fast that the difference between an O(n) and an O(n^2) algorithm is barely perceptible.
- **Large Inputs**:
  As the input dataset grows larger, O(n^2) algorithms curve upwards steeply and slow down drastically compared to linear O(n) algorithms.

## 3. Dropping Non-Dominant Terms (O(n + n^2) → O(n^2))

What if a method has an independent single loop followed by a nested loop?

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers) {
        // Single loop: O(n)
        for (const number of numbers) {
            console.log(number);
        }

        // Nested loops: O(n^2)
        for (const first of numbers) {  // O(n)
            for (const second of numbers) {  // O(n)
                console.log(first + ", " + second);
            }
        }
    }
    ```

    </Tab>

    <Tab value="Java">

    ```java
    public class Main {
        public void log(int[] numbers) {
            // Single loop: O(n)
            for (int number : numbers) {
                System.out.println(number);
            }

            // Nested loops: O(n^2)
            for (int first : numbers) {  // O(n)
                for (int second : numbers) {  // O(n)
                    System.out.println(first + ", " + second);
                }
            }
        }
    }
    ```
    </Tab>
</Tabs>

### Why O(n + n^2) Simplifies to O(n^2):
1. Combining both parts gives:
   `Total Operations = O(n + n^2)`
2. **The Dominance Rule**:
   - In Big O analysis, we only focus on the term that has the greatest impact on performance as `n` grows towards infinity.
   - When `n = 1,000`:
     - `n = 1,000`
     - `n^2 = 1,000,000`
   - The `n` term contributes only 0.1% of the total operations. Its effect is negligible compared to `n^2`.
3. Therefore, we **drop the non-dominant term (`n`)** and simplify to **O(n^2)**.

## 4. Extending to Three Nested Loops: O(n^3) (Cubic Time)

What if we nest three loops together?

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers) {
        // O(n^3) - Cubic Time
        for (const first of numbers) {  // O(n)
            for (const second of numbers) {  // O(n)
                for (const third of numbers) {  // O(n)
                    console.log(first + ", " + second + ", " + third);
                }
            }
        }
    }
    ```

    </Tab>
    <Tab value="Java">

    ```java
    public class Main {
        public void log(int[] numbers) {
            // O(n^3) - Cubic Time
            for (int first : numbers) {  // O(n)
                for (int second : numbers) {  // O(n)
                    for (int third : numbers) {  // O(n)
                        System.out.println(first + ", " + second + ", " + third);
                    }
                }
            }
        }
    }
    ```

    </Tab>
</Tabs>

### Complexity Analysis:
- Total operations: `n * n * n = n^3`.
- Runtime complexity is **O(n^3)** (Cubic Time).
- An O(n^3) algorithm scales even worse than O(n^2) and quickly becomes impractical for moderately large datasets.

## Summary Checklist

| Metric | Details |
| :--- | :--- |
| **Complexity** | O(n^2) (Quadratic Time) |
| **Growth Rate** | Steep curved parabola upward |
| **Rule: Drop Non-Dominant Terms** | O(n + n^2) → O(n^2) |
| **Three Nested Loops** | O(n * n * n) = O(n^3) (Cubic Time) |
| **Scalability** | Poor for large datasets |
| **Common Examples** | Nested loops, bubble sort, selection sort, finding all pairs in an array |
