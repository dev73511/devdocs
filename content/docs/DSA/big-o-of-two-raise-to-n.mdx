## What is O(2^n)?

**O(2^n)**, pronounced **"Big O of 2 to the power of n"** (or **"2 raised to n"**), represents **Exponential Time** complexity.

In an O(2^n) algorithm, the growth rate **doubles with each addition to the input dataset**. 

- If `n = 1`: **2 operations** (2^1)
- If `n = 2`: **4 operations** (2^2)
- If `n = 3`: **8 operations** (2^3)
- If `n = 10`: **1,024 operations** (2^10)
- If `n = 20`: **1,048,576 operations** (over 1 million operations!)
- If `n = 30`: **1,073,741,824 operations** (over 1 billion operations!)
- If `n = 50`: **1,125,899,906,842,624 operations** (over 1 quadrillion operations!)

Because the growth shoots nearly vertically upward, exponential algorithms are **not scalable at all** and rapidly become impractical even for small inputs.

---

## Exponential Growth vs. Logarithmic Growth

Exponential growth is the **opposite of logarithmic growth**:

- The **logarithmic curve** (`O(log n)`) slows down as the input size grows.
- The **exponential curve** (`O(2^n)`) grows **faster and faster**.

An algorithm that runs in exponential time is **not scalable at all**. It will become very slow very soon.

---

## Example: Recursive Fibonacci

A common example of an algorithm that runs in exponential time is the recursive calculation of Fibonacci numbers:

<Tabs items={['JavaScript', 'Java']}>
<Tab value="JavaScript">

```javascript
// O(2^n) - Exponential Time
function fibonacci(n) {
    if (n <= 1) {
        return n;
    }

    // Each call branches into two more calls
    return fibonacci(n - 1) + fibonacci(n - 2);
}
```

</Tab>

<Tab value="Java">

```java
public class Main {
    // O(2^n) - Exponential Time
    public static int fibonacci(int n) {
        if (n <= 1) {
            return n;
        }

        // Each call branches into two recursive calls
        return fibonacci(n - 1) + fibonacci(n - 2);
    }
}
```

</Tab>

</Tabs>

### Why it runs in O(2^n):
- Each call branches into **two more recursive calls**: `fibonacci(n - 1)` and `fibonacci(n - 2)`.
- With each step the input increases, the total number of operations roughly **doubles**.
- Because operations double with each addition to `n`, it quickly triggers millions or billions of function calls for even modest values of `n`.

## The 5 Fundamental Big O Curves

These five growth rates we have covered are the ones you will see most of the time across data structures and algorithms:

| Complexity | Name | Performance | Growth Behavior |
| :--- | :--- | :--- | :--- |
| **O(1)** | Constant Time | Ideal / Best | Runs in constant time; unaffected by input size. |
| **O(n)** | Linear Time | Fair / Good | Grows at the same steady rate in direct proportion to input size. |
| **O(n^2)** | Quadratic Time | Poor | Curves upward; gets slower as input size grows. |
| **O(log n)** | Logarithmic Time | Excellent | Slows down and flattens out as input size grows. |
| **O(2^n)** | Exponential Time | Horrible / Worst | The opposite of logarithmic; grows faster and faster and is not scalable at all. |
