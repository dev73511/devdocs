## What is O(n)?

**O(n)**, pronounced **"Big O of n"**, represents **Linear Time** complexity.

In an O(n) algorithm, the execution time (or number of operations) **grows linearly and in direct proportion to the size of the input dataset (n)**.

- If the input has **1 item**, it runs **1 operation**.
- If the input has **10 items**, it runs **10 operations**.
- If the input has **1,000,000 items**, it runs **1,000,000 operations**.

Unlike O(1) where input size is irrelevant, here the size of the input directly drives the total computational cost.

---

## 1. Basic Loop Example

The most common example of O(n) is a loop that iterates over all elements of an array.

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers) {
        // O(n)
        for (let i = 0; i < numbers.length; i++) {
            console.log(numbers[i]);
        }

        // Alternatively, using a for...of loop:
        // for (const number of numbers) {
        //     console.log(number);
        // }
    }
    ```

    </Tab>

    <Tab value="Java">

    ```java
    public class Main {
        public void log(int[] numbers) {
            // O(n)
            for (int i = 0; i < numbers.length; i++) {
                System.out.println(numbers[i]);
            }

            // Alternatively, using an enhanced for-each loop:
            // for (int number : numbers) {
            //     System.out.println(number);
            // }
        }
    }
    ```

    </Tab>
    
</Tabs>

### Loop Type Does Not Matter
Whether you write:
- A traditional `for` loop
- An enhanced `for-each` / `for...of` loop
- A `while` loop or `do-while` loop

As long as the loop visits each item in the input of size `n` once, the time complexity remains **O(n)**.

## 2. Dropping Non-Dominant Constants (O(2 + n) → O(n))

What happens if we execute constant-time operations before or after the loop?

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers) {
        console.log(); // O(1)

        for (const number of numbers) { // O(n)
            console.log(number);
        }

        console.log(); // O(1)
    }
    ```

    </Tab>
    <Tab value="Java">

    ```java
    public class Main {
        public void log(int[] numbers) {
            System.out.println(); // O(1)

            for (int number : numbers) { // O(n)
                System.out.println(number);
            }

            System.out.println(); // O(1)
        }
    }
    ```

    </Tab>
</Tabs>

### Why O(1 + n + 1) Simplifies to O(n):
1. **Calculating individual steps**:
   `Total Operations = O(1) + O(n) + O(1) = O(2 + n)`
2. **Dropping constants**:
   - If `n = 1,000,000`, executing 2 additional single-step operations (1,000,002 vs 1,000,000) has virtually no noticeable impact.
   - The growth curve is still dictated entirely by `n`.
   - Therefore, we drop the constant `+2` and simplify the complexity to **O(n)**.

## 3. Multiple Consecutive Loops (O(2n) → O(n))

What happens if we run two separate loops iterating over the same input array?

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers) {
        // First loop: O(n)
        for (const number of numbers) {
            console.log(number);
        }

        // Second loop: O(n)
        for (const number of numbers) {
            console.log(number);
        }
    }
    ```

    </Tab>

    <Tab value="Java">

    ```java
    public class Main {
        public void log(int[] numbers) {
            // First loop: O(n)
            for (int number : numbers) {
                System.out.println(number);
            }

            // Second loop: O(n)
            for (int number : numbers) {
                System.out.println(number);
            }
        }
    }
    ```

    </Tab>
</Tabs>

### Why O(n + n) = O(2n) Simplifies to O(n):
1. **Summing the loops**:
   `O(n) + O(n) = O(2n)`
2. **Dropping constant multipliers**:
   - Big O is not about exact instruction counts; it is an approximation of how the algorithm scales.
   - Both `n` and `2n` represent a straight diagonal line — **linear growth**.
   - As `n` grows very large, the constant multiplier `2` becomes insignificant in describing the rate of growth.
   - Therefore, we drop the constant coefficient `2` to get **O(n)**.

## 4. Multiple Different Inputs (O(n + m))

What if a method receives two distinct inputs with different sizes?

<Tabs items={['JavaScript', 'Java',]}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers, names) {
        // O(n) - where n is the length of numbers
        for (const number of numbers) {
            console.log(number);
        }

        // O(m) - where m is the length of names
        for (const name of names) {
            console.log(name);
        }
    }
    ```

    </Tab>
    <Tab value="Java">

    ```java
    public class Main {
        public void log(int[] numbers, String[] names) {
            // O(n) - where n is the length of numbers
            for (int number : numbers) {
                System.out.println(number);
            }

            // O(m) - where m is the length of names
            for (String name : names) {
                System.out.println(name);
            }
        }
    }
    ```

    </Tab>
</Tabs>

### Distinguishing Between Inputs:
- Here, we do not have a single array size. `numbers` might have 10 elements while `names` has 1,000,000 elements (or vice versa).
- We use separate variables:
  - Let `n` = length of `numbers`
  - Let `m` = length of `names`
- Total runtime complexity is **O(n + m)**.
- And Once again we can simplify this to **O(n)**. Because the runtime of this method increases linearly.
- Because both inputs grow independently and linearly, the overall relationship is linear with respect to both inputs.

## Summary Checklist

| Metric | Details |
| :--- | :--- |
| **Complexity** | O(n) (Linear Time) |
| **Growth Rate** | Straight diagonal line (linear slope) |
| **Rule 1: Drop Constants** | O(2 + n) → O(n) |
| **Rule 2: Drop Multipliers** | O(2n) → O(n) |
| **Rule 3: Multiple Inputs** | Two separate inputs of lengths `n` and `m` yield O(n + m) |
| **Common Examples** | Iterating through an array, linear search, copying an array |
