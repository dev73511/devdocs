## What is O(n)?

**O(n)**, pronounced **"Big O of n"**, represents **Linear Time** complexity.

In an O(n) algorithm, the execution time (or number of operations) **grows linearly and in direct proportion to the size of the input (n)**.

- If the input has **1 item**, it runs **1 operation**.
- If the input has **10 items**, it runs **10 operations**.
- If the input has **1,000,000 items**, it runs **1,000,000 operations**.

Unlike O(1) where input size is irrelevant, here the size of the input directly drives the total computational cost.

---

## 1. Basic Loop Example

Here we have an example with a loop iterating over an array:

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers) {
        // O(n)
        for (let i = 0; i < numbers.length; i++) {
            console.log(numbers[i]);
        }

        // Alternatively, using a for...of loop:
        // for (const number of numbers) {
        //     console.log(number);
        // }
    }
    ```

    </Tab>

    <Tab value="Java">

    ```java
    public class Main {
        public void log(int[] numbers) {
            // O(n)
            for (int i = 0; i < numbers.length; i++) {
                System.out.println(numbers[i]);
            }

            // Alternatively, using an enhanced for-each loop:
            // for (int number : numbers) {
            //     System.out.println(number);
            // }
        }
    }
    ```

    </Tab>
</Tabs>

### How it works:
- We are iterating over all the items in this array and printing each item on the console.
- This is where the size of the input matters:
  - If we have a single item in the array, we have **1 print operation**.
  - If we have 1 million items, we have **1 million print operations**.
- So the cost of this algorithm grows linearly and in direct correlation to the size of the input.
- We represent the runtime complexity of this method using **O(n)** , where **n** represents the size of the input.

### Loop Type Does Not Matter:
It doesn't matter what kind of loop we use to iterate over the array:
- Traditional `for` loop
- Enhanced `for-each` / `for...of` loop
- `while` loop or `do-while` loop

In all cases, we are still iterating over all the items in the array, so the runtime complexity is **O(n)**.

## 2. Adding Print Statements Before and After (Dropping Constants)

Now, what if we have a print statement before and after our loop?

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers) {
        console.log(); // O(1)

        for (const number of numbers) { // O(n)
            console.log(number);
        }

        console.log(); // O(1)
    }
    ```

    </Tab>
    <Tab value="Java">

    ```java
    public class Main {
        public void log(int[] numbers) {
            System.out.println(); // O(1)

            for (int number : numbers) { // O(n)
                System.out.println(number);
            }

            System.out.println(); // O(1)
        }
    }
    ```

    </Tab>
</Tabs>

### Why O(1 + n + 1) Simplifies to O(n):
- The single print statements run in constant time: `O(1)`.
- The loop runs in linear time: `O(n)`.
- So the runtime complexity is `O(1 + n + 1)`, which simplifies to `O(2 + n)`.
- However, in Big O notation, we **drop these constants** because they don't really matter.
- **Reason**: If our array has 1 million items, adding 2 extra operations doesn't really have a significant impact on the cost of our algorithm. The cost still increases linearly.
- What matters is that the cost increases linearly and in direct proportion to the size of our input:
  - If we have 5 items, we have 5 operations.
  - If we have a million items, we have a million operations.
- Therefore, we drop the constant **2** and simplify to **O(n)**.

## 3. Multiple Loops Over the Same Array (Dropping Multipliers)

Now, what if we have two separate loops iterating over the same array?

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers) {
        // First loop: O(n)
        for (const number of numbers) {
            console.log(number);
        }

        // Second loop: O(n)
        for (const number of numbers) {
            console.log(number);
        }
    }
    ```

    </Tab>

    <Tab value="Java">

    ```java
    public class Main {
        public void log(int[] numbers) {
            // First loop: O(n)
            for (int number : numbers) {
                System.out.println(number);
            }

            // Second loop: O(n)
            for (int number : numbers) {
                System.out.println(number);
            }
        }
    }
    ```

    </Tab>
</Tabs>

### Why O(n + n) = O(2n) Simplifies to O(n):
- The first loop runs in `O(n)` and the second loop runs in `O(n)`.
- The combined runtime complexity is `O(n + n)` or `O(2n)`.
- This is another example where we **drop the constant**, because all we need here is an approximation of the cost of the algorithm relative to its input size.
- Both `n` and `2n` still represent **linear growth**.
- Therefore, we drop the multiplier `2` and write **O(n)**.

## 4. Two Different Inputs (O(n + m))

What if this method had two parameters: an array of numbers and an array of names?

<Tabs items={['JavaScript', 'Java']}>
    <Tab value="JavaScript">

    ```javascript
    function log(numbers, names) {
        // O(n) - where n is the length of numbers
        for (const number of numbers) {
            console.log(number);
        }

        // O(m) - where m is the length of names
        for (const name of names) {
            console.log(name);
        }
    }
    ```

    </Tab>
    <Tab value="Java">

    ```java
    public class Main {
        public void log(int[] numbers, String[] names) {
            // O(n) - where n is the size of numbers
            for (int number : numbers) {
                System.out.println(number);
            }

            // O(m) - where m is the size of names
            for (String name : names) {
                System.out.println(name);
            }
        }
    }
    ```

    </Tab>
</Tabs>

### Distinguishing Between Inputs:
- Both loops run in linear time, but here we have **two inputs** (`numbers` and `names`), not just one.
- We need to distinguish between the two input sizes:
  - Let `n` be the size of the first input (`numbers`)
  - Let `m` be the size of the second input (`names`)
- The runtime complexity is **O(n + m)**.
- And once again, we can simplify our understanding because the runtime of this method increases linearly with the size of each input.

## Summary Checklist

| Metric | Details |
| :--- | :--- |
| **Complexity** | O(n) (Linear Time) |
| **Growth Rate** | Straight diagonal line (cost increases in direct proportion to input size) |
| **Rule 1: Drop Constants** | O(2 + n) simplifies to O(n) |
| **Rule 2: Drop Multipliers** | O(2n) simplifies to O(n) |
| **Rule 3: Multiple Inputs** | Two separate inputs of sizes `n` and `m` yield O(n + m) |
| **Common Examples** | Iterating over an array, linear search, copying an array |
